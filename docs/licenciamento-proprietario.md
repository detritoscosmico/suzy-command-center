# Política de licenciamento proprietário

Data da decisão: 21 de agosto de 2026 (America/Sao_Paulo).

## Decisão

O Suzy Command Center adota, nesta fase, política de **software proprietário / todos os direitos reservados** para os materiais originais do repositório, salvo quando um arquivo, dependência, ativo ou componente de terceiro declarar licença própria.

A decisão preserva controle sobre reutilização, redistribuição, comercialização, sublicenciamento, hospedagem concorrente e criação de derivados do núcleo proprietário. O repositório ser público no GitHub não o transforma em software open source.

O aviso principal está no arquivo `LICENSE`.

## Escopo

A política cobre, quando originais do projeto:

- código-fonte;
- documentação;
- estrutura e organização do projeto;
- interfaces e materiais visuais;
- textos e materiais educacionais;
- regras, fluxos, componentes e demais artefatos protegíveis.

A política não reivindica direitos sobre componentes de terceiros além dos direitos efetivamente existentes.

## Componentes de terceiros

Dependências, bibliotecas, widgets, marcas, dados, serviços externos e outros materiais de terceiros continuam submetidos às suas próprias licenças e termos. A política proprietária da Suzy não substitui essas obrigações.

Antes de distribuir comercialmente uma versão, a lista de dependências e avisos de terceiros deve continuar sendo revisada.

## Repositório público

A visibilidade pública permite inspeção e colaboração conforme os recursos e termos do GitHub, mas não concede uma licença geral para copiar, modificar, redistribuir, sublicenciar, vender ou explorar comercialmente os materiais proprietários.

Se o projeto passar a conter segredos comerciais, credenciais, chaves, dados pessoais ou componentes cuja confidencialidade seja necessária, esses materiais não devem depender de copyright como controle de acesso e precisam ser removidos do repositório público ou mantidos em ambiente privado apropriado.

## Contribuições externas

A política proprietária cria uma exigência adicional de governança para contribuições externas. Antes de incorporar código ou conteúdo de terceiros ao núcleo proprietário, deve existir autorização clara e compatível para uso, modificação, redistribuição e eventual exploração comercial.

Enquanto não houver processo formal de contribuição, CLA, DCO ou outro instrumento apropriado, contribuições externas relevantes não devem ser tratadas automaticamente como transferindo direitos ao projeto apenas porque foram enviadas por pull request.

## Uso comercial e permissões

Licenças comerciais, redistribuição, sublicenciamento, parcerias ou permissões especiais devem ser autorizadas expressamente pelo titular dos direitos. O arquivo `LICENSE` não concede licença comercial pública.

## Relação com releases

A existência de uma versão em `package.json`, uma tag Git ou um GitHub Release não altera a política proprietária. Cada release deve preservar o aviso de copyright/licenciamento e as obrigações de terceiros aplicáveis.

## Limites

Esta política registra a decisão de governança do projeto e não substitui análise jurídica específica para contratos, cessão de direitos, licenciamento comercial, contribuições externas, marcas, proteção de dados ou distribuição em jurisdições específicas.
